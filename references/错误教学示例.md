# 错误教学示例

这些模式来自学习者明确拒绝的课堂体验。项目教学时避开它们；它们不是可接受的简写版本。

## 1. 用技术栈或执行过程当标题

```markdown
# 【FastAPI + React】从 python main.py 到首页出现
```

问题：标题只描述了经过哪些技术和动作，学习者无法预先知道本节要掌握什么概念。

改为一个明确的知识范围，例如：

```markdown
# 【HTTP】请求、响应、重定向、超时与原始页面保存
```

或：

```markdown
# 【Web 应用】浏览器、前端、后端与服务器的分工
```

## 2. 把文件、结论或目录图放在概念之前

```text
先列出 main.py、src/app.py、frontend/、dist/
    -> 直接概括每个文件的责任
    -> 再补一小段概念解释
```

问题：文件名不能建立因果理解。学习者还不知道“前端”“后端”“构建产物”是什么，就无法从目录推断责任。

## 3. 假定初学者认识看到的术语或日志

```text
终端出现两行地址
    -> 前端一个，后端一个
```

问题：初学者只看到了两行陌生文字，不知道“前端”“后端”“端口”“日志”分别是什么。不能要求学习者根据陌生输出自行分类。

正确做法是先说清：现在启动了哪个程序、它做什么、为什么观察这一行、这一行能证明什么，以及它不能证明什么。

## 4. 先钻项目代码，再补通用概念

```text
看到 app.mount、FileResponse、StaticFiles
    -> 逐行解释
    -> 最后才说明“静态文件服务”是什么
```

问题：代码中的名字会堆积为记忆负担，学习者无法知道这些东西解决的共同问题，也无法迁移到其他项目。

## 5. 只给结论，不让现象自然推出机制

```text
Python 没有运行 React；FastAPI 返回了构建产物。
```

问题：即使结论正确，学习者仍不知道为什么要有构建产物、浏览器为什么需要它、FastAPI 为什么需要处理文件请求。

## 6. 在一个章节同时深挖多个知识系统

```text
FastAPI 路由
    -> React 组件树
    -> Vite 构建
    -> HTTP
    -> SSE
```

问题：整体协作可以提到这些边界，但单节只深入标题指定的一个知识系统。跨边界时明确标注“这里只说明合作关系，后续专节展开”。

## 7. 在还没建立概念前要求复述项目代码

```text
请说明 GET / 如何进入 read_index，并区分 FileResponse 和 StaticFiles。
```

问题：这会把学习检查变成术语记忆。先检查白话理解和通用链路，再进入代码级追踪。

## 自检信号

若本节开头出现大量未经解释的词，例如 `Uvicorn`、`FastAPI`、`dist`、`FileResponse`、`StaticFiles`、`端口`，或先出现文件职责表而学习者还不知道这些对象是什么，应停止并按正确示例重写。
