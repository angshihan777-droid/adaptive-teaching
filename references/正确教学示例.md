# 正确教学示例

这份文件定义项目驱动、初学者友好的课程形状。重点不是套用某个项目的内容，而是让学习者从可观察现象逐步形成可迁移的内部知识。

## 核心顺序

```text
学习者在项目中能直接看到什么
    -> 用日常语言提出“为什么会这样”
    -> 先讲解决这个问题所需的通用概念
    -> 给出完整但简单的概念链路
    -> 一个最小示例解释对象、输入、处理和输出
    -> 再回到项目找代码证据
    -> 明确本节边界与后续章节
    -> 学习者先用自己的话解释
```

项目是提出问题和验证知识的载体；概念学习本身才是课堂主体。

## 初学者视角的课前引入

从学习者确实能观察到的事物开始，不假设其已经知道术语。

例如，不说：

```text
前端在 5173，后端在 8000。
```

而说：

```text
你在终端里看到两行带网址的文字。现在不要求你猜它们分别是什么。
我们先确认：刚才运行了哪条命令？这条命令启动的是一个什么程序？
然后才解释这个程序为什么打印网址、网址中的数字代表什么。
```

课前引入的固定写法：

```markdown
## 课前引入：<一个从项目中看见的直白现象>

先描述学习者看见的文件、页面、按钮、终端文字或运行结果。
说明“现在只需认识这个现象，不需要预先知道术语”。
提出一个自然的为什么问题。
指出本章会用什么概念回答它。
```

## 先讲概念，再映射代码

以“为什么只启动 Python 也能看到页面”为例，正确节奏是：

```text
先看见：项目有 Python 文件、前端目录和构建后的文件；启动后有页面
    -> 先解释浏览器、前端、后端和服务器程序分别是什么
    -> 再解释它们一次协作的大致过程
    -> 最后打开项目代码，验证谁把什么文件交给浏览器
```

不要反过来先讲 `FileResponse` 和 `StaticFiles`。这两个名字应在学习者已经理解“浏览器需要服务器把文件交给它”之后才出现，并且出现时立刻解释其普通含义。

## 专有名词的引入规则

每个陌生名词第一次出现时，按以下顺序介绍：

```text
它解决什么眼前问题
    -> 白话定义
    -> 在当前链路中处于哪一步
    -> 最小例子
    -> 准确技术名称和项目中的代码位置
```

例如：

```text
浏览器拿到首页后还会需要图片、样式和 JavaScript 文件。
服务器不能只认识首页，还要能根据文件地址找出这些普通文件并返回。
这种“按地址从一个目录返回文件”的能力叫静态文件服务。
FastAPI 中的 StaticFiles 是实现它的一个工具。
```

## 单章边界与标题

标题必须展示学习到的概念，而不是技术栈拼接或执行流水。

```markdown
# 【HTTP】请求、响应、重定向、超时与原始页面保存
```

单章只深入一个知识系统。可以先给出整个应用的协作图，但跨系统时只说明接口：

```text
FastAPI 把已经准备好的前端文件交给浏览器。
浏览器如何运行 React 并形成组件树，留到【React】专节讲解。
```

## 概念课的正文骨架

```markdown
# 【类别】具体概念

## 本节速览
## 课前引入：项目中的直白现象
## 先看完整的通用过程
## 基础概念
## 最小示例
## 映射到当前项目：代码如何证明这个过程
## 当前边界：本节不展开什么
## 你先用自己的话解释
```

“映射到当前项目”必须位于核心概念之后。代码用于证明和具体化，不用于替代解释。

## 学习检查

先问能反映因果理解的白话问题：

```text
用户填写信息并看到结果时，浏览器、前端和后端分别做了什么？
```

学习者答完后，再根据需要进入术语、代码位置和调用链检查。学习者可以回答“不知道”；把缺口作为下一段教学材料，不用标准答案覆盖其思路。
