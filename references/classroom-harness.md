# Classroom Harness

Use this as a final behavioral check, not as a learner-facing form unless useful.

## Before the learner turn

- Did the lesson begin with an observable project phenomenon?
- Did it ask a plain-language “why” question?
- Were general concepts explained before project identifiers?
- Was each unfamiliar term introduced through the problem it solves?
- Did the lesson stay within one knowledge system?

## After the learner turn

- Can the learner state the input, output, call order, and responsibility boundaries in plain language?
- Did the correction distinguish factual accuracy, missing reasoning, and terminology?
- Is there evidence from a file, run, test, or observed output?
- Are non-goals and remaining uncertainty explicit?
- Is the next topic a natural continuation rather than an unrelated expansion?

## Red flags

Stop and repair the lesson if it starts with a file inventory, raw logs, a framework name cluster, a conclusion without a causal chain, or a request to recite code before concepts exist.
