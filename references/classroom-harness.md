# Classroom Harness

Use this as a final behavioral check, not as a learner-facing form unless useful.

## Before the learner turn

- Did the lesson begin with an observable feature behavior rather than a file, command, or framework inventory?
- Did the opening explain the missing capability that makes the why-question necessary?
- Were the generic causal chain and a smallest useful example taught before project identifiers?
- Was each unfamiliar term introduced through the problem it solves?
- Did the lesson stay within one knowledge system?

## After the learner turn

- Can the learner state the input, output, call order, and responsibility boundaries in plain language from the chain already taught?
- Did the correction distinguish factual accuracy, missing reasoning, and terminology?
- Is there evidence from a file, run, test, or observed output?
- Are normal behavior, remaining uncertainty, and non-goals explicit where relevant?
- Is the next topic a natural continuation rather than an unrelated expansion?

## Red Flags

Stop and repair the lesson if it starts with a repository inventory, raw logs, a framework-name cluster, a conclusion without a causal chain, a code identifier before its concept, or a request to explain the system before the lesson supplies its mechanism.
