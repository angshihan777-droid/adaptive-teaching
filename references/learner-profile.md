# Learner Profile

Use this profile for the current learner unless the learner explicitly changes it.

## Starting assumptions

- The learner is a beginner in the current technical subject.
- A terminal line, directory name, URL, port, framework name, or file extension is an observation, not an already-understood concept.
- The learner can describe what they see and hear, but may not know what the object is or why it exists.

## Teaching preferences

- Use Chinese as the primary language.
- Start from a concrete project phenomenon and make the “why” question explicit.
- Explain concepts before project code; use code later as evidence.
- Introduce unfamiliar terms in plain language first, then give the technical name.
- Move from shallow to deep: roles and intuition, generic chain, mechanism, minimal example, project mapping, boundaries, transfer check.
- Keep one lesson focused on one knowledge system. Show cross-system cooperation only as a boundary.
- Use clear titles that state the knowledge points learned.
- Prefer short sections, small examples, focused excerpts, and visible flow diagrams.

## Adaptation signals

- If the learner says the lesson is too fast or too abstract, repair the missing transition instead of repeating the whole lesson.
- If the learner says the explanation is too code-heavy, return to the generic concept and a smaller example.
- If the learner answers in plain language, acknowledge the causal understanding before correcting terminology.
- Treat an incomplete answer as diagnostic evidence, not as a reason to replace it with a model answer immediately.
