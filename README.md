# adaptive-teaching

面向中文学习者的源码驱动教学 Skill，服务两个目标：

- 通过真实项目源码准备 Agent 应用开发秋招；
- 在理解设计和源码之后，逐步实现自己的最小 Web 项目。

它不要求学习者通读仓库，也不把所有技术都讲到同样深度。学习从一个真实行为开始，先建立设计思路，再用源码验证，最后留下运行、复述、面试和个人项目证据。

## 核心教学模型

### 两节独立课程

概念课和源码课必须分开，但使用同一个知识锚点连接。

概念课负责：

- 现实中为什么需要这个设计；
- 最简单方案有什么问题；
- 真实工作时要考虑什么；
- 如何读接口文档、写交接信息和记录取舍；
- 个人项目应该保留、简化还是替换什么。

源码课负责：

- 在 Khoj 中定位同一个设计；
- 追踪真实调用关系和数据变化；
- 说明源码如何实现概念课的设计；
- 找出实现差异、失败边界和可观察证据。

关系是：

```text
概念课：为什么这样设计、工作中如何协作
→ 知识锚点
→ 源码课：Khoj 如何实现和验证这个设计
```

### 知识锚点

每组课程都要有一个稳定的锚点，例如：

`AGENT-ROUTING-01：任务分流、能力选择与执行边界`

同一锚点下，概念课和源码课不能换主题、换主线或互相失联。

### 深度分配

- 后端：细讲请求生命周期、数据契约、分层、失败处理和工程取舍。
- Agent：细讲上下文、决策、RAG、Tool、Skill、模型边界和可验证性。
- 前端：只讲请求构造、事件消费和与后端协作的部分。
- 通信协议：先复用已有笔记；没有笔记时只补最低必要的代码模型。
- 框架内部和页面工程：默认只讲职责与输入输出，除非阻塞主链。

## 学习者已有知识

如果用户提供了已学笔记库，开始课程前先读取与当前行为直接相关的笔记。

Khoj 学习中的已学笔记目录是：

```text
D:\docs\obsidian_note\self_study\obsidian-notes\KHOJ\内容
```

已有笔记覆盖的知识默认不重讲，只做以下工作：

- 对照 Khoj 的具体实现；
- 指出对象、字段或职责差异；
- 补充阻塞当前后端或 Agent 主链的最小连接；
- 发现错误时标记 `[补充-纠正]`，不直接改旧笔记。

## 推荐课程流程

### 概念课

标题使用知识点总结式格式，例如：

```markdown
# 【Agent】任务分流、能力选择与执行边界
```

概念课不贴大段 Khoj 源码，按以下顺序推进：

1. 现实问题；
2. 设计为什么需要；
3. 简单方案的缺陷；
4. 真实工作中的接口、失败、维护、文档和交接；
5. 个人项目的取舍；
6. 知识锚点；
7. 下一节源码课的验证目标；
8. 一个理解问题。

### 源码课

源码课引用同一个锚点，按真实调用顺序追踪：

1. 回顾概念课留下的设计问题；
2. 定位文件、函数和调用者；
3. 展示必要的连续源码；
4. 解释输入、转换、输出和失败路径；
5. 对照概念课说明实现是否一致；
6. 回收接口文档、交接和故障定位要点。

源码不是第一次解释陌生技术的材料，也不能脱离概念锚点逐行翻译。

## 输出风格

- 主标题是知识点总结，不使用完整问句。
- 普通中文流程直接写成短句，例如：`请求 → 会话 → Agent → 上下文`。
- 不使用 `text` 代码块承载普通中文。
- 不重复堆叠标题、列表和箭头流程。
- 先用连续短段落讲清因果，再使用少量分点。
- 类比只解释一个关系，并立即说明对应的真实对象。

## 进度和验收

学习计划应独立于 Skill，使用用户项目中的索引和分文件计划。

一个节点只有在具备以下证据后，才能标记为 `[已通关]`：

- 源码定位和调用链理解；
- 运行、测试或日志证据；
- 学习者自己的复述；
- 概念题、源码题和工程追问；
- 个人项目中的最小实现或明确取舍记录。

只听过、看过或讲过的内容保持 `[待验证]`，不能直接宣布掌握。

## 个人项目节奏

采用垂直切片：完成一个闭合能力后，实现一个最小版本。

推荐顺序：

1. 聊天输入与模型回答；
2. 会话和历史上下文；
3. 流式输出；
4. Markdown 导入与检索；
5. Tool / Skill 分流；
6. 错误、安全、日志、测试和部署。

不要求复制 Khoj 的全部复杂度。每次都记录：Khoj 的设计、自己的方案、保留或替换的原因，以及运行证据。

## 使用示例

开始学习：

```text
使用 adaptive-teaching，读取我的学习计划、当前进度和与本节相关的已有笔记。
先进行概念课，讲清设计思路、真实工作中的考虑、文档和交接要求；不要贴 Khoj 源码。
```

进入源码课：

```text
继续同一个知识锚点的源码课。
请回顾概念课的设计，再在 Khoj 中按真实调用顺序验证实现，重点讲后端和 Agent。
```
